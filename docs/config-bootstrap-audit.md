# Selective new-machine configuration audit

The source audit recorded 70 top-level entries under `~/.config` on 2026-10-14 UTC. The versioned decision for every name is in `config/bootstrap/config-policy.json`. Its `path` values are relative to `~/.config`; a more specific file record states the exception inside a mixed directory. The historical metadata snapshot is private: `mori://shinzui/dotfiles-private.nix`, project-relative `docs/audits/2026-10-14-config-bootstrap.json` (artifact URI pending). The public policy contains no account identifiers or credential values.

The additional selected tool configuration is limited to `nhub`, `ntn`, `nihongo`, `seihou`, Nagare, gcloud, and kubectl. `nihongo/config.kdl` and `seihou/config.dhall` are the only new public editable sources. The nhub and ntn whole configs contain literal KDL token nodes, so the private companion encrypts them. Gcloud profile settings, the selected Nagare local files, and `~/.kube/config` have private recovery records. Tailscale preferences live outside XDG configuration and are recovered by enrolling a distinct new device, not by copying its plist or node state.

Existing Home Manager, Nix, and agenix declarations retain their ownership. In particular, GitHub CLI's `config.yml` is managed while `hosts.yml` is renewed through authentication; Television's Nix search channel is generated while its other settings remain unselected; Direnv's integration is managed while its extra preference is unselected. Neovim's linked sources and generated startup file have separate owners. Caddy's autosave, caches, logs, extension state, and token databases are regenerated or omitted. No application is enabled merely because an old settings directory exists.

Mori's `config.dhall` and audited source skills are individual editable links. Its `host-id` is local machine state. The source Mac's original was backed up outside Git before removing it from tracking. A new Mac starts without a copied ID and lets Mori create one. Existing Kazuha and Rei tracked trees contain source settings and skills, with no observed per-machine identity; their current declarations remain.

Unselected application preferences default to `exclude`. Possible unique user data in Anthropic, Cai, Raycast, or Yarn is `data-export`: review and export wanted material with its owning application rather than transferring whole directories. Historical Mori/Rei backup configs differ from active source but have no old-only setting keys; the active files add settings. Mori's backup has one old-only `automation-config` skill absent from its current source and producing repository. These backups remain `data-export` until that skill's desired ownership is decided; the bootstrap does not copy their whole trees. Source skills under NTN, Seihou, and Testkit are unselected installation trees. Worktrunk's active file mixes approvals and absolute paths with preferences, and Karabiner has device-specific settings; neither is copied. The Mole cleanup list should be reviewed before any later cleanup, which is outside this bootstrap. Empty directories, logs, caches, sockets, installation records, and stale backups are not transfer payloads.

The policy is a selection list, not a copy command. The checker validates selected source file types without following symlinks and reports existing destination conflicts without overwriting them. Exact sensitive source and destination mappings, plus account-specific recovery, live only in the private companion's `config/bootstrap/private-policy.json` (artifact URI pending under `mori://shinzui/dotfiles-private.nix`).
